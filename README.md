# YouTube Video Tools

Набор локальных инструментов для обслуживания скачанного видеоархива. Проект работает с файловыми именами, метаданными контейнеров и `yt-dlp`; видео не загружаются в репозиторий и не используются в CI.

## Быстрый старт и управление меню

В Windows запустите `video_tools.bat` или выполните из папки программы:

```powershell
py -3 video_tools.py
```

Без аргументов открывается меню. Введите номер и нажмите Enter.
Сначала рекомендуется пункт **1**, затем нужная операция. Вверху меню показан
архив, с которым выполняются действия: проверяйте этот путь перед изменениями.
После выполнения остаётся последний вывод; Enter возвращает в меню. Пункт **0**
завершает программу. Вызов CLI с именем команды выполняет её один раз, без меню.

В обычных подтверждениях `[Y/n]` принимаются `y` / `д` без учёта регистра;
пустой ответ означает согласие. Для отказа введите `n` / `н`.
Выбор перекачивания `R / S / RA / SA` имеет отдельные правила: пустой или
неизвестный ответ не разрешает замену. Ctrl+C прерывает текущую операцию;
уже завершённые изменения автоматически не откатываются.

В примерах ниже `video-tools` доступен после установки пакета. Без установки
можно заменить его на `py -3 video_tools.py`. Общие параметры ставятся **до**
имени команды, параметры конкретной команды **после**:

```powershell
video-tools --root "D:\Video\Youtube" --quiet dates
video-tools --root "D:\Video\Youtube" bookmarks --dry-run
video-tools --folder "Имя канала" report
```

`--quiet` скрывает обычные сообщения и прогресс, но не ошибки, предупреждения
и запросы подтверждения; он не означает автоматическое согласие. `--verbose`
показывает дополнительную диагностику. Не все команды используют общий фильтр
папок одинаково: у субтитров собственный список папок, у сортировки только корень,
а `download` работает с плейлистом, а не с выбранной локальной папкой.

## Все функции меню

| № | Пункт | Эквивалент CLI | Что меняет |
| --- | --- | --- | --- |
| 1 | Проверить окружение (doctor) | `video-tools doctor` | Временная проба записи, служебное состояние |
| 2 | Скачать избранное YouTube | `video-tools download` | Видео, архив загрузок, при необходимости резервная копия архива |
| 3 | Скачать субтитры | `video-tools subtitles` | Файлы субтитров рядом с видео |
| 4 | Предпросмотр переименования | `video-tools rename --dry-run` | Кэш метаданных; имена не меняет |
| 5 | Выполнить переименование | `video-tools rename --apply` | Имена файлов, журнал и кэш |
| 6 | Предпросмотр сортировки | `video-tools resort --dry-run` | Не перемещает файлы |
| 7 | Выполнить сортировку | `video-tools resort --apply` | Пути видео и связанных файлов, журнал и кэш |
| 8 | Отменить последнюю сортировку | `video-tools resort --undo-last` | Возвращает файлы по журналу |
| 9 | Найти дубли | `video-tools duplicates` | Кэш метаданных; файлы не удаляет |
| 10 | Проверить даты в именах | `video-tools dates` | Только отчёт |
| 11 | Проверить разрешение видео | `video-tools resolution` | Только отчёт |
| 12 | Создать CSV-инвентаризацию | `video-tools inventory` | `inventory.csv` |
| 13 | Проверить архив загрузок | `video-tools archive-sync --dry-run` | Только план |
| 14 | Синхронизировать архив загрузок | `video-tools archive-sync --apply` | Архив загрузок и его резервная копия |
| 15 | Отчёт о проблемах архива | `video-tools report` | Только отчёт; CSV при явном `--output` |
| 16 | Обновить закладки SponsorBlock | `video-tools bookmarks --apply` | Главы в контейнерах или подтверждённое перекачивание, состояние и журнал |
| 0 | Выход | Завершение меню | Ничего |

### 1. Проверить окружение (doctor)

Диагностика перед первым запуском или после переноса программы. Проверяет
Python, конфигурацию, папку архива, cookies, доступность `yt-dlp`, `ffprobe`
и `ffmpeg`, свободное место, возможность записи, журнал и кэш.
Для проверки записи создаётся и удаляется временный файл; видео не анализируются.
Ошибки следует исправить до запуска изменяющих операций. Успешная проверка
наличия cookies не доказывает, что авторизация YouTube ещё действительна.

### 2. Скачать избранное YouTube

Название пункта историческое: скачивается **«Смотреть позже» (`WL`)**, а не
список понравившихся видео. Нужны сеть, `yt-dlp`, cookies авторизованного аккаунта
и `ffmpeg` для объединения потоков/обработки; для восстановления нужен `ffprobe`.

1. Проверяет наличие cookies-файла и выводит его путь, но не содержимое.
2. По умолчанию синхронизирует `yt-dlp-archive.txt` с локальными именами видео.
   Устаревшие записи удаляются без отдельного вопроса, с резервной копией;
   отключение: `[download] sync_archive_before_download = false`.
3. Загружает доступные новые ролики с ограничением до 720p, предпочитая MP4/M4A.
4. Сохраняет в папку автора по шаблону
   `Автор/Название_ДД.ММ.ГГГГ [YouTubeID].расширение`.
5. Помечает категории SponsorBlock; физически удаляет `sponsor`, `interaction`
   и `selfpromo`. Сам пакет не запрашивает создание `.info.json` рядом с видео.

Процент относится к текущему потоку: смена «Видео» на «Аудио» не означает
повторную загрузку всего ролика. После 100% ещё могут идти объединение и запись
глав. Итоговая строка успеха появляется после завершения обработки.

При ошибке повторной обрезки уже существующего видео после окончания процесса
появляется адресное восстановление: `R` — перекачать этот файл, `S` — пропустить,
`RA` — перекачать все такие файлы, `SA` — пропустить все. Оригинал заменяется
только после проверки нового файла; неподтверждённый путь или изменение оригинала
отменяют замену. Очередь существует только в текущем запуске. Это не повторный
проход по всему архиву. Ненулевой код исходной загрузки сохраняется даже после
восстановления, чтобы не скрыть остальные ошибки.

Если YouTube сообщает, что плейлист не существует, файл cookies может при этом
быть на месте: проверьте аккаунт и обновите cookies. Это не доказательство
отсутствия файла на диске.

### 3. Скачать субтитры

Скачивает **автоматические** субтитры YouTube к уже сохранённым видео, не загружая
сами видеопотоки. YouTube ID определяется из имени. Уже имеющиеся субтитры
нужного языка пропускаются. Файлы сохраняются рядом с соответствующим видео.

Папки и языки задаются в `[subtitles]` (`folders`, `languages`); стандартные
языки — `ru` и `en`. **При пустом списке папок пункт меню ничего не обрабатывает.**
Обход каждой указанной папки нерекурсивный. CLI позволяет выбрать папки и языки:

```powershell
video-tools subtitles --folder "Имя канала" --lang ru --lang en
```

Доступность автосубтитров зависит от видео. Между запросами используется пауза;
`--pause` и `--timeout` настраивают её и таймаут. Отсутствие YouTube ID приводит
к пропуску. Успешный ответ сервиса не гарантирует наличие автосубтитров всех языков.

### 4. Предпросмотр переименования

Рекурсивно находит подходящие имена с YouTube ID, получает дату публикации из
кэша или через `yt-dlp` и показывает план добавления `_ДД.ММ.ГГГГ` перед `[ID]`.
Обрабатываться могут и связанные файлы, например `Название [ID].ru.vtt`.
Корректная уже существующая дата не дублируется; некорректная календарная дата
подлежит замене. При занятом целевом имени файл пропускается.

Имена и содержимое файлов не меняются, но кэш полученных дат сохраняется.
Для новых сведений нужна сеть. Это предварительная проверка перед пунктом 5,
а не сохранённое разрешение на будущие изменения.

### 5. Выполнить переименование

Выполняет тот же расчёт, что пункт 4, и реально меняет имена подходящих файлов.
Содержимое видео не перекодируется. Успехи и ошибки записываются в журнал;
конфликтующие имена не перезаписываются.

**В меню есть предварительное подтверждение. В CLI `rename --apply` сразу
выполняет операцию без этого дополнительного вопроса.** Специальной команды
отмены переименования нет: пункт 8 относится только к сортировке. Перед массовой
обработкой используйте предпросмотр и резервную копию важных данных.

### 6. Предпросмотр сортировки

Строит план переноса в папки авторов. Важно: берёт видео **непосредственно из
корня архива**, а не пересортировывает рекурсивно уже существующие папки каналов.
Автор определяется по распознанному источнику/ID, с использованием метаданных
и кэша. Вместе с видео планируются связанные файлы, включая субтитры.

Не перемещает файлы. Если автор не определён, по умолчанию пропускает видео;
размещение в `Unknown` разрешается отдельно через `--allow-unknown` или настройки.
При конфликтах план подбирает свободные имена, а не заменяет существующие файлы.
Сеть может потребоваться для получения автора.

### 7. Выполнить сортировку

Строит план как пункт 6, выполняет предварительные проверки доступности путей
и записи, показывает количество перемещений и запрашивает подтверждение.
После согласия создаёт необходимые папки авторов и перемещает файлы;
содержимое видео не меняет. CLI-флаг `--yes` отключает вопрос.

Перемещения фиксируются в журнале для последующей отмены. Ошибка части операций
не означает, что все предыдущие перемещения автоматически отменены: смотрите
итог и журнал. Перед запуском завершите другие процессы, работающие с этими файлами.

### 8. Отменить последнюю сортировку

По журналу находит последний подходящий завершённый и ещё не отменённый запуск
сортировки, проверяет обратные пути и возвращает перемещённые файлы.
При отсутствии текущего файла или занятом исходном пути отмена может быть отклонена.

**Выбор пункта сразу запускает отмену, без дополнительного вопроса.**
Не отменяет скачивание, переименование, синхронизацию архива или обновление глав.
Не является восстановлением удалённых файлов. Для работы нужен сохранённый журнал.

### 9. Найти дубли

Выполняет два независимых поиска:

- Точные копии: сначала группирует файлы по размеру, затем читает содержимое
  кандидатов и сравнивает SHA-256. На большом архиве это может быть долго.
- Одинаковый YouTube ID: показывает файлы одного ролика. При доступном названии
  из YouTube/кэша отмечает наиболее похожее имя, но это не оценка качества видео.

Одинаковый ID не доказывает одинаковое содержимое: разрешение, главы или обрезка
могут отличаться. Ничего не удаляет и не выбирает автоматически файл для удаления.
Для названий возможны сетевые запросы; кэш метаданных сохраняется. При отсутствии
совпадений явно выводится «Дубли не найдены».

### 10. Проверить даты в именах

Проверяет имена видео на наличие даты формата `ДД.ММ.ГГГГ` и календарную
корректность. Показывает файлы без даты (`MISSING`) и с неправильной датой
(`INVALID`), затем сводку. Не обращается к YouTube, не читает видеопотоки,
не исправляет имена и не сравнивает дату с реальной датой публикации.

При найденных проблемах возвращает код 1; в quiet-режиме сводка остаётся
предупреждением. Для исправления используйте сначала пункт 4, затем пункт 5.

### 11. Проверить разрешение видео

Для каждого выбранного видео вызывает `ffprobe` и выводит ширину и высоту
первого видеопотока, например `1280x720`. Нужен доступ к контейнеру видео;
интернет не требуется. Не изменяет разрешение и не перекодирует файлы.

Если параметры прочитать не удалось, выводит предупреждение с путём и итоговое
количество неудач; код завершения — 1. Само наличие разрешения не является
полной проверкой целостности всех кадров или звука.

### 12. Создать CSV-инвентаризацию

Рекурсивно собирает файловые метаданные, не читая видеопотоки и не обращаясь
к YouTube. По умолчанию создаёт или **перезаписывает** `<root>/inventory.csv`
без подтверждения. Формат: UTF-8 с BOM, разделитель `;`, подходит для импорта в Excel.

Колонки: папка, относительный путь, имя, расширение, размер в байтах, тип источника,
ID, дата из имени, число субтитров и список их имён. Дата здесь берётся из имени,
а не проверяется по YouTube; для проверки используйте пункт 10.

```powershell
video-tools inventory --output "D:\Reports\video-inventory.csv"
```

CSV содержит сведения о вашем архиве и не должен попадать в публичный репозиторий.

### 13. Проверить архив загрузок

Сравнивает записи `youtube ID` в `yt-dlp-archive.txt` с ID локальных видео и
показывает, какие записи устарели: соответствующего файла больше нет.
Работает по именам файлов, без сети и чтения видеопотоков. Ничего не удаляет
и не добавляет отсутствующие в текстовом архиве ID существующих видео.

По умолчанию текстовый архив находится в корне видео; другой файл можно задать
через `--archive`. Отсутствующий архив трактуется как пустой. Проверку лучше
выполнять на полном архиве: ограничение папок может исключить реально существующие
в других папках видео из сравнения.

### 14. Синхронизировать архив загрузок

Выполняет план пункта 13: после подтверждения удаляет устаревшие YouTube ID
из текстового архива. Сначала создаёт рядом резервную копию
`yt-dlp-archive.txt.backup-<метка времени>`, затем атомарно записывает результат.
Если удалять нечего, не переписывает архив и не создаёт копию. CLI: `--yes`
позволяет пропустить подтверждение.

**Не удаляет видео и не удаляет ролики из «Смотреть позже» на YouTube.**
Если просмотренное видео удалено локально, его ID удалён из архива загрузок,
но ролик остался в плейлисте, следующая загрузка может скачать его заново.
Чтобы этого не происходило, удалите просмотренный ролик из плейлиста на YouTube.
Не применяйте синхронизацию к случайно ограниченному набору папок.

### 15. Отчёт о проблемах архива

По именам и расположению файлов выявляет: отсутствие распознанного ID, отсутствие
или некорректность даты, отсутствие папки автора и отсутствие связанных субтитров.
«Нет папки автора» означает, что файл лежит прямо в корне; правильность названия
канала в существующей подпапке не проверяется. Содержимое субтитров тоже не проверяется.

Не читает видеопотоки, не требует сети, не исправляет найденное. В меню выводит
отчёт на экран; CLI может создать/перезаписать CSV:

```powershell
video-tools report --output "D:\Reports\video-issues.csv"
```

Обнаруженные неполные метаданные здесь являются результатом отчёта, а не сбоем:
сама команда при успешной работе возвращает 0, даже если проблемы найдены.

### 16. Обновить закладки SponsorBlock

Закладки — это **главы внутри видеоконтейнера**, а не отдельный текстовый файл.
Для YouTube-видео программа читает локальные главы/длительность через `ffprobe`,
получает удалённые метаданные через `yt-dlp` и строит план изменений.
Нужны сеть, `yt-dlp`, `ffprobe`, `ffmpeg`; cookies используются, если настроены.

1. Перечисляет подходящие видео и пытается восстановить незавершённый проход.
2. Для необработанных файлов сравнивает локальные главы и актуальные данные;
   показывает план и краткие различия названий глав.
3. Сохраняет `bookmarks-plan.txt` и состояние сканирования.
4. Перед массовой записью глав просит подтверждение. Запись выполняет через
   временный контейнер без перекодирования, проверяет результат и заменяет оригинал.
5. Для физически обрезанных видео предлагает `R / S / RA / SA`. При согласии
   скачивает видео заново и применяет актуальные сегменты. Повторно использовать
   исходные временные метки на уже сокращённом файле небезопасно.

`10 -> 9` означает число глав до и после обновления, а не удаление одного видео.
`PLAN` — только расчёт; `APPLY` — стадия записи. `STALE` означает, что оригинал
изменился после сканирования: такая замена отменяется. При отказе от применения
план сохраняется для продолжения. Временные ограничения YouTube имеют повторные
попытки с паузой; во время возобновления записи `retry_later` проверяются повторно.

Каждый запуск снова перечисляет файлы. При сохранённом незавершённом проходе
неизменившиеся обработанные записи используются повторно; новые или изменившиеся
файлы проверяются. После завершения работы состояние прохода очищается, поэтому
следующий полный запуск снова проверяет архив. Постоянного кэша «не проверять
SponsorBlock несколько дней» сейчас нет.

Для предварительного просмотра без изменения контейнеров:

```powershell
video-tools bookmarks --dry-run
video-tools --folder "Имя канала" bookmarks --apply
video-tools bookmarks --apply --ffmpeg-timeout 1200
```

`--timeout` относится к сетевым операциям, `--ffmpeg-timeout` — к переписи глав;
`--pause-seconds`, `--max-retries`, `--retry-backoff-seconds` управляют паузами и
повторами. Для переписи больших файлов необходимо свободное место под временную
копию. Перекачивание может изменить размер/качество по действующему профилю
загрузки до 720p; это не восстановление вырезанных фрагментов из локальных данных.

### 0. Выход

Закрывает меню без дополнительных операций с файлами. Незавершённые действия
не продолжаются в фоне автоматически. Для продолжения сохранённого прохода
SponsorBlock снова запустите пункт 16.

## Рабочие сценарии и ограничения

- Первый запуск: **1**, затем **2**. Cookies нужны именно от нужного аккаунта.
- Приведение имён в порядок: **10 → 4 → 5**. Предпросмотр не заменяет резервную копию.
- Раскладка видео из корня: **6 → 7**; при необходимости отмена через **8**.
- Учёт архива: **12** для полного CSV, **15** для перечня проблем.
- Удалили просмотренные видео: уберите их из «Смотреть позже», затем **13 → 14**.
- Ошибка повторной обрезки при загрузке: используйте адресное восстановление
  в конце пункта **2**, а не запускайте весь пункт **16** ради нескольких файлов.

Коды CLI: `0` — команда выполнена (иногда это только отчёт или отказ пользователя),
`1` — обнаруженные проблемы/частичные ошибки, `2` — ошибка запуска или настроек,
`130` — прерывание. Внешний `yt-dlp` может возвращать свой код. Подробности следует
читать в логе; один код не заменяет итоговую сводку.

Предпросмотр означает отсутствие изменений медиафайлов, но не обязательно
полное отсутствие записи: кэш, план и служебное состояние могут обновляться.
Пакет не синхронизирует просмотр с YouTube и не удаляет дубли автоматически.

## Стабилизация перед Stage 2

Загрузка и перекачивание SponsorBlock используют общий индикатор на основе
структурированных событий yt-dlp. В интерактивном терминале обновляется одна
строка с названием, процентом и отдельными стадиями «Видео» / «Аудио»;
после загрузки видны объединение потоков и обработка глав.
Завершение отдельного потока не оставляет строку успеха: единственная `✓`
для обычной загрузки появляется по `after_move`. При перекачивании успех
выводится только после проверки нового файла и атомарной замены оригинала.
Перед загрузкой `before_dl` показывает
«Подготовка». В TTY строки `✓` и `>` выводятся без дополнительных status-тегов;
в машинном логе сохраняются `[OK]` и `[INFO]`.
Строка подстраивается под ширину терминала, цвета ANSI не используются.
При перенаправлении, в CI и `TERM=dumb` выводятся обычные строки с ограничением
частоты. `--quiet` оставляет только предупреждения и ошибки, `--verbose`
добавляет техническую диагностику yt-dlp. Итог считает видео только после
подтверждённого завершения обработки (`after_move`), а не по числу потоков;
неизвестное количество пропущенных файлов не показывается.
Runtime-зависимости не добавлены; yt-dlp устанавливается в Quality job только
для проверки совместимости машинных шаблонов с настоящим форматтером.

При ошибке SponsorBlock `Cannot cut video since the real and expected durations mismatch`
команда `download` собирает очередь адресного восстановления. После завершения
yt-dlp доступны ответы `R` (перекачать), `S` (пропустить), `RA` (перекачать все),
`SA` (пропустить все), без учёта регистра. EOF и неинтерактивный stdin означают
пропуск, а не согласие; quiet также не подтверждает замену автоматически.
ID и абсолютный путь берутся из структурированного события ModifyChapters;
неизвестные, внешние, перенаправленные или изменившиеся файлы не заменяются.
Используется временная загрузка с проверкой ffprobe и атомарной заменой.
После успеха ID добавляется в архив загрузок без дубликатов. Дополнительного
сканирования видеоархива нет; первоначальная синхронизация архива не изменена.
Итог отдельно показывает восстановленные, пропущенные и неудачные операции.
Ненулевой код исходного yt-dlp сохраняется даже после восстановления: другие
ошибки плейлиста не маскируются. Очередь действует в пределах текущего запуска.

План SponsorBlock хранит `schema_version` и идентичность каждого файла:
ID, относительный путь, размер и `mtime_ns`. Старые планы без этих полей
пересканируются. Изменившийся после scan файл получает сообщение `STALE`
и не перезаписывается: следующий запуск построит новый план.

CLI использует единый exclusive lock для любых записывающих команд,
включая dry-run с обновлением cache/state, инвентаризацию и загрузку субтитров.
Наличие старого файла `archive.lock` само по себе не блокирует запуск:
блокировку удерживает операционная система, а не содержимое файла.

Рабочие журналы и план размещаются через `state_directory(root)`.
Явные пользовательские CSV-экспорты сохраняют прежние пути `--output`;
инвентаризация по умолчанию по-прежнему пишет `<root>/inventory.csv`.
Временные медиаконтейнеры создаются рядом с оригиналом для атомарной замены.

Журнал пропускает только оборванную последнюю JSONL-запись без переноса строки;
повреждение середины диагностируется и запрещает дальнейшую запись.
На Windows процессы завершаются через `taskkill /T`, на POSIX через process group;
завершение дочерних процессов является best-effort и не распространяется на
намеренно отделившиеся процессы.

Первый reusable API: `dates.run(Options(...), AppContext(...)) -> CommandResult`.
Он не меняет `sys.argv` и окружение. Остальные команды пока используют legacy
адаптер CLI; прямой вызов их внутренних helpers требует блокировки со стороны вызывающего кода.
Настройки представлены dataclass `Settings`; все существующие поля необязательны
и имеют прежние значения по умолчанию.

Проверки из каталога проекта:

```powershell
py -3 -m unittest discover -s tests -v
py -3 tests/verify_layouts.py
py -3 -m compileall youtube_video_tools tests
ruff check .
ruff format --check .
```

`verify_layouts.py` создаёт четыре чистые временные копии исходников и тестов:
обычная/relocated структура, без config/с заведомо некорректным config и внешними
настройками. Пользовательские cookies и видео не копируются. Отдельных тестов
реального YouTube/видеоархива нет; process-тесты запускают только тестовый Python.

## Установка

Требуется Python 3.11 или новее. Внешние программы `yt-dlp`, `ffprobe` и `ffmpeg` должны быть доступны в `PATH` либо указаны в конфигурации.

```powershell
python -m pip install -e .
video-tools doctor
```

Для разработки и проверок установите Ruff:

```powershell
python -m pip install ruff
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

## Запуск

### Отдельная папка программы

Для локального видеоархива репозиторий можно разместить в подкаталоге
`_video_tools`. В этом случае архивом по умолчанию служит родительская папка,
а `config.toml`, `.git`, `.github`, тесты и кэши разработки остаются внутри
`_video_tools`. Состояние архива (журнал, кэш метаданных и результаты сканирования
SponsorBlock) хранится в `_video_tools/.video-tools`. При переносе существующей
установки эту папку нужно перенести целиком, предварительно завершив программу.
Файл `yt-dlp-archive.txt` остаётся рядом с видео.

В папке видео можно оставить BAT-обёртку, запускающую
`python "%~dp0_video_tools\video_tools.py" %*` из этой папки.
Команды разработки и Git выполняются из `_video_tools`.
При явном `--root` для другого архива его состояние по-прежнему хранится
в `.video-tools` внутри выбранного архива. Обычная структура клонированного
репозитория и команды CI не меняются.

Старый способ запуска сохранён:

```powershell
python video_tools.py
python video_tools.py doctor
python video_tools.py bookmarks --dry-run
```

После установки доступна console-команда:

```powershell
video-tools doctor
video-tools download
```

В Windows можно также запустить `video_tools.bat`.

## Конфигурация

Скопируйте `config.example.toml` в локальный `config.toml` и при необходимости задайте пути к cookies и внешним программам. Реальный `config.toml` игнорируется Git и никогда не должен публиковаться.

Приоритет настроек: аргументы CLI, переменные окружения, `config.toml`, значения по умолчанию. Например:

```powershell
$env:VIDEO_TOOLS_ROOT = 'D:\Video\Youtube'
$env:YOUTUBE_COOKIES_FILE = 'D:\Secrets\youtube-cookies.txt'
video-tools doctor
```

## Команды

- `doctor` — проверка Python, конфигурации, root, cookies, `yt-dlp`, `ffprobe`, `ffmpeg`, журнала и кэша.
- `download` — загрузка новых видео из «Смотреть позже».
- `bookmarks` — обновление встроенных глав SponsorBlock.
- `subtitles` — загрузка автоматических субтитров.
- `rename` — добавление даты публикации в имя файла.
- `resort` — раскладка файлов по папкам автора и отмена последнего запуска.
- `duplicates` — точные дубли и повторяющиеся YouTube ID.
- `dates`, `resolution`, `inventory`, `report`, `archive-sync` — проверки и отчёты архива.

Команды, изменяющие архив, получают межпроцессный lock. JSON-кэш и состояние сканирования SponsorBlock записываются атомарно. Перед заменой видео результат `ffmpeg` или перекачивания проверяется `ffprobe`.
