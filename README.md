# YouTube Video Tools

Набор локальных инструментов для обслуживания скачанного видеоархива. Проект работает с файловыми именами, метаданными контейнеров и `yt-dlp`; видео не загружаются в репозиторий и не используются в CI.

## Стабилизация перед Stage 2

Загрузка и перекачивание SponsorBlock используют общий индикатор на основе
структурированных событий yt-dlp. В интерактивном терминале обновляется одна
строка с названием, процентом и отдельными стадиями «Видео» / «Аудио»;
после загрузки видны объединение потоков и обработка глав.
Строка подстраивается под ширину терминала, цвета ANSI не используются.
При перенаправлении, в CI и `TERM=dumb` выводятся обычные строки с ограничением
частоты. `--quiet` оставляет только предупреждения и ошибки, `--verbose`
добавляет техническую диагностику yt-dlp. Итог считает видео только после
подтверждённого завершения обработки (`after_move`), а не по числу потоков;
неизвестное количество пропущенных файлов не показывается.
Runtime-зависимости не добавлены; yt-dlp устанавливается в Quality job только
для проверки совместимости машинных шаблонов с настоящим форматтером.

План SponsorBlock хранит `schema_version` и идентичность каждого файла:
ID, относительный путь, размер и `mtime_ns`. Старые планы без этих полей
пересканируются. Изменившийся после scan файл получает сообщение `STALE`
и не перезаписывается: следующий запуск построит новый план.

CLI использует единый exclusive lock для любых записывающих команд,
включая dry-run с обновлением cache/state, инвентаризацию и загрузку субтитров.
Наличие старого файла `archive.lock` само по себе не блокирует запуск:
блокировку удерживает операционная система, а не содержимое файла.

Рабочие журналы и план размещаются через `state_directory(root)`.
Явные пользовательские CSV-экспорты сохраняют прежние пути `--output`;
инвентаризация по умолчанию по-прежнему пишет `<root>/inventory.csv`.
Временные медиаконтейнеры создаются рядом с оригиналом для атомарной замены.

Журнал пропускает только оборванную последнюю JSONL-запись без переноса строки;
повреждение середины диагностируется и запрещает дальнейшую запись.
На Windows процессы завершаются через `taskkill /T`, на POSIX через process group;
завершение дочерних процессов является best-effort и не распространяется на
намеренно отделившиеся процессы.

Первый reusable API: `dates.run(Options(...), AppContext(...)) -> CommandResult`.
Он не меняет `sys.argv` и окружение. Остальные команды пока используют legacy
адаптер CLI; прямой вызов их внутренних helpers требует блокировки со стороны вызывающего кода.
Настройки представлены dataclass `Settings`; все существующие поля необязательны
и имеют прежние значения по умолчанию.

Проверки из каталога проекта:

```powershell
py -3 -m unittest discover -s tests -v
py -3 tests/verify_layouts.py
py -3 -m compileall youtube_video_tools tests
ruff check .
ruff format --check .
```

`verify_layouts.py` создаёт четыре чистые временные копии исходников и тестов:
обычная/relocated структура, без config/с заведомо некорректным config и внешними
настройками. Пользовательские cookies и видео не копируются. Отдельных тестов
реального YouTube/видеоархива нет; process-тесты запускают только тестовый Python.

## Установка

Требуется Python 3.11 или новее. Внешние программы `yt-dlp`, `ffprobe` и `ffmpeg` должны быть доступны в `PATH` либо указаны в конфигурации.

```powershell
python -m pip install -e .
video-tools doctor
```

Для разработки и проверок установите Ruff:

```powershell
python -m pip install ruff
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

## Запуск

### Отдельная папка программы

Для локального видеоархива репозиторий можно разместить в подкаталоге
`_video_tools`. В этом случае архивом по умолчанию служит родительская папка,
а `config.toml`, `.git`, `.github`, тесты и кэши разработки остаются внутри
`_video_tools`. Состояние архива (журнал, кэш метаданных и результаты сканирования
SponsorBlock) хранится в `_video_tools/.video-tools`. При переносе существующей
установки эту папку нужно перенести целиком, предварительно завершив программу.
Файл `yt-dlp-archive.txt` остаётся рядом с видео.

В папке видео можно оставить BAT-обёртку, запускающую
`python "%~dp0_video_tools\video_tools.py" %*` из этой папки.
Команды разработки и Git выполняются из `_video_tools`.
При явном `--root` для другого архива его состояние по-прежнему хранится
в `.video-tools` внутри выбранного архива. Обычная структура клонированного
репозитория и команды CI не меняются.

Старый способ запуска сохранён:

```powershell
python video_tools.py
python video_tools.py doctor
python video_tools.py bookmarks --dry-run
```

После установки доступна console-команда:

```powershell
video-tools doctor
video-tools download
```

В Windows можно также запустить `video_tools.bat`.

## Конфигурация

Скопируйте `config.example.toml` в локальный `config.toml` и при необходимости задайте пути к cookies и внешним программам. Реальный `config.toml` игнорируется Git и никогда не должен публиковаться.

Приоритет настроек: аргументы CLI, переменные окружения, `config.toml`, значения по умолчанию. Например:

```powershell
$env:VIDEO_TOOLS_ROOT = 'D:\Video\Youtube'
$env:YOUTUBE_COOKIES_FILE = 'D:\Secrets\youtube-cookies.txt'
video-tools doctor
```

## Команды

- `doctor` — проверка Python, конфигурации, root, cookies, `yt-dlp`, `ffprobe`, `ffmpeg`, журнала и кэша.
- `download` — загрузка новых видео из «Смотреть позже».
- `bookmarks` — обновление встроенных глав SponsorBlock.
- `subtitles` — загрузка автоматических субтитров.
- `rename` — добавление даты публикации в имя файла.
- `resort` — раскладка файлов по папкам автора и отмена последнего запуска.
- `duplicates` — точные дубли и повторяющиеся YouTube ID.
- `dates`, `resolution`, `inventory`, `report`, `archive-sync` — проверки и отчёты архива.

Команды, изменяющие архив, получают межпроцессный lock. JSON-кэш и состояние сканирования SponsorBlock записываются атомарно. Перед заменой видео результат `ffmpeg` или перекачивания проверяется `ffprobe`.
